## Перед работой

Определи затрагиваемое приложение и кратко назови его владельцу. Для каждого
затрагиваемого Git-репозитория отдельно проверь status/diff и сохрани чужие правки.
Git-команды выполняй с явным рабочим каталогом нужного репозитория.

Перед любым изменением склада обязательно вручную прочитай
`C:/Projects/sklad-zapchastey/AGENTS.md`, `docs/project-map.md`, инструкции
выбранного направления и соответствующие подробные правила. Дополнительная
папка Codex не гарантирует автоматического чтения её инструкций.
Для сайта начни с `docs/parts-storefront.md`; история выпуска и отчёты находятся
также в `C:/Projects/nikolacars/docs/`.

без отдельного поручения. Не отменяй правки других исполнителей.

## Два отдельных выпуска

У сайта и склада остаются отдельные Git-истории, зависимости, проверки,
резервные копии, квитанции и процедуры публикации. Общая рабочая область
не разрешает массовую публикацию обоих приложений или объединение репозиториев.
Определяй полный согласованный runtime scope; исключай документацию, тестовые
данные, local-only operators, секреты и чужие правки из production payload.

Склад публикуется только штатным `scripts/release-live.ps1` по его правилам.
Сайт публикуется отдельным проверенным scoped оператором с live baseline,
SHA guards и материалами отката по текущей документации сайта.
При зависимом изменении API/витрины сначала выпускай совместимое расширение
backend, проверяй контракт, затем frontend. Записывай результаты для каждого
приложения отдельно. Разрешение на один выпуск не расширяй на другой автоматически.

Проектные данные смотри через встроенный браузер или разрешённое чтение БД.
Личный Chrome, записи в бизнес-данные, отправки, активации и обходы доступа
не подразумеваются работой с общей областью. Секреты и резервные архивы
не добавляй в Git. Текущие правила каждого приложения продолжают действовать.
