## Подтверждённая проблема карточек

Для 63 ID API каталога отдавал в поле применимости название складской партии. Проверены все 63 детальные страницы. На 45 витрина подставила сведения справочника, а у 18 метка вида «TESLA MY 2020 - 2023 залишки» попала в видимое поле совместимости и в текст описания. Как минимум одна из этих карточек, 113507, уже была в индексе по индивидуальной проверке. Google не указывает эту пометку в качестве причины исключения. [Пример 106900](https://nikolacars.kiev.ua/parts/1494154-00-a-106900/) · [Предыдущая индивидуальная проверка 113507](gsc-errors-2026-10-31.md)

Метка видна у товаров 103592, 103679, 106837, 106840, 106900, 106918, 106936, 107000, 113154, 113507, 113510, 113514, 113515, 113520, 113521, 113573, 113582 и 113591. Для каждого адрес с подтверждённой пометкой указан в файле результатов.

В `app/Services/ProductCatalogFacts.php` из публичного поля совместимости исключена строка, которая целиком совпадает с форматом названия партии. Период в такой строке характеризует складскую партию и сам по себе не подтверждает применимость конкретной детали. Справочная совместимость, отдельные поля модели и корректного VIN продолжают отображаться. Один контрольный запрос с локальными фикстурами воспроизвёл дефект. После правки все 12 изолированных сценариев прошли вместе с проверкой корректного обнаружения ошибок. Маршруты обеих локалей проверены через API и HTML. [Регрессионная проверка](../../tests/product-fitment-regression.php) · [Локальное подтверждение](../../.codex-tmp/compat-regressions/run-d21e91664c16)

Исправление опубликовано 1 ноября. После публикации в 14:29 по Киеву независимо проверены все 36 страниц на украинском и русском. Каждая открылась с HTTP 200 без редиректов с ожидаемым ID, исходным canonical и отдельным полем модели. Складская пометка исчезла из видимого поля применимости, описания, данных карточки и описания в разметке Product. [Результаты 36 HTTP-проверок](gsc-instock-2026-11-01-evidence.json)
